# Operational and Analytical Data Systems

## Operational Versus Analytical Systems

* **Operational systems:** Handle day-to-day business operations, such as processing orders, payments, and user registrations.
* **Analytical systems:** Analyze large amounts of data to identify trends, generate reports, and support decision-making.

## OLTP Versus OLAP

| Feature    | OLTP                                   | OLAP                                  |
| ---------- | -------------------------------------- | ------------------------------------- |
| Full form  | Online Transaction Processing          | Online Analytical Processing          |
| Purpose    | Handle operational transactions        | Analyze data                          |
| Queries    | Simple, frequent, and short            | Complex, often involving aggregations |
| Data       | Current operational data               | Historical and consolidated data      |
| Operations | Inserts, updates, deletes, and lookups | Scans, aggregations, and joins        |
| Example    | Processing a customer order            | Analyzing yearly sales                |

## OLAP vs Real-Time / Product Analytics

* **Traditional OLAP:** Analyzes large datasets, often using historical data in a data warehouse.
* **Real-time analytics:** Processes incoming data continuously or with minimal delay to provide up-to-date insights.
* **Product analytics:** Examines user behavior, such as clicks, sessions, conversions, and feature usage.

**Key distinction:** Traditional OLAP often focuses on historical analysis, while real-time and product analytics emphasize timely insights and user behavior.

## OLTP Database → ETL/ELT → Data Warehouse → OLAP

Typical analytical data pipeline:

* **OLTP database:** Stores operational data generated by applications.
* **ETL/ELT:** Moves data from operational systems into analytical storage.

  * ETL: Extract, Transform, Load.
  * ELT: Extract, Load, Transform.
* **Data warehouse:** Stores structured, integrated data optimized for analysis.
* **OLAP:** Queries the warehouse to perform aggregations, reporting, and analytical investigations.

**Purpose:** Separate analytical workloads from operational workloads to avoid interfering with day-to-day transactions.

## Hybrid Transactional / Analytical Processing (HTAP)

* Combines OLTP and OLAP capabilities within a single database system.
* Allows transactional and analytical workloads to operate on the same underlying data, while the system abstracts their different processing requirements.
* Reduces the need to move data into a separate warehouse before analysis.

**Key benefit:** Enables fresher analytics without relying entirely on a separate ETL pipeline.

## Data Lake

* Stores data in its raw or near-original form, as produced by operational systems.
* Can accommodate structured, semi-structured, and unstructured data.
* Schema and transformations can often be applied when the data is read and analyzed.

**Key idea:** Preserve the original data so it can be processed in different ways later.

## Data Lake vs Data Warehouse

| Feature    | Data Lake                                 | Data Warehouse                           |
| ---------- | ----------------------------------------- | ---------------------------------------- |
| Data       | Raw or minimally processed                | Cleaned, transformed, and structured     |
| Schema     | Often schema-on-read                      | Typically schema-on-write                |
| Data types | Structured, semi-structured, unstructured | Primarily structured                     |
| Purpose    | Flexible storage and exploration          | Reporting and analytical queries         |
| Users      | Data engineers, data scientists, analysts | Analysts and business intelligence users |

## Sushi Principle: "Raw Data Is Better"

* Retaining raw data is valuable because transformations may discard information.
* Raw data can be reprocessed later using improved methods or for new analytical requirements.
* Once information is discarded during transformation, it may be difficult or impossible to recover.

**Key idea:** Preserve raw data whenever practical rather than keeping only transformed results.

## Reverse ETL

* Moves processed or analytical data from a data warehouse back into operational applications.
* Makes analytical insights available to business tools and operational workflows.

**Example:** Sending customer segments from a warehouse into a CRM system for targeted customer interactions.

* **Traditional ETL:** Operational systems → Data warehouse.
* **Reverse ETL:** Data warehouse → Operational systems.

## Systems of Record

* A **system of record**, also called a **source of truth**, stores the authoritative or canonical version of data.
* It is generally the primary place where data is first written and maintained.
* Other systems may obtain copies of its data for different purposes.

**Example:** A company's customer database may be the authoritative source for customer account information.

## Derived Data Systems

* Store data produced by transforming, processing, or combining data from existing systems.
* Examples include indexes, caches, materialized views, search indexes, and recommendation systems.
* Improve query performance or support queries that the system of record cannot answer efficiently.

**Key idea:** Derived data can generally be regenerated from its source data, provided the necessary inputs and transformation logic are available.

## Systems of Record vs Derived Data Systems

| Feature  | Systems of Record                  | Derived Data Systems                             |
| -------- | ---------------------------------- | ------------------------------------------------ |
| Role     | Authoritative source of data       | Store processed or transformed data              |
| Data     | Primary, canonical data            | Data derived from other sources                  |
| Writes   | Usually receive primary writes     | Often updated from source systems                |
| Purpose  | Maintain correctness and authority | Improve performance or enable additional queries |
| Examples | Primary databases                  | Caches, indexes, search systems                  |

**Relationship:**

* Systems of record prioritize maintaining authoritative data.
* Derived data systems make that data easier or faster to access for specific use cases.
* Derived systems must be kept sufficiently synchronized with their sources to avoid serving stale or inconsistent information.
